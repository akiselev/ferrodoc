# FDX6 integration validation

FP6 validates the already bounded FP0-FP5 contracts as one portable flow. A checked-in real,
purpose-built image-only PDF is surveyed and converted to a deterministic fixture baseline. The
baseline produces an immutable delta, logical state manifest, and canonical DocumentIR checkpoint.
A Pareto-planned, page-qualified table request then appends exact-span table evidence to one region.
The prior text evidence remains resolvable while the region's selected view advances to the table
hypothesis.

The integration oracle proves all of the following in one execution:

- PDF survey, full-document baseline, state manifest, and checkpoint production;
- exact page-qualified targeted scheduling through the normal enrichment runtime;
- old evidence-anchor retention and a refined selected evidence view;
- cold durable execution followed by a separate worker's verified warm reuse;
- byte-identical full-delta and baseline-checkpoint-plus-tail materialization;
- a versioned `ExternalEvidencePin` containing only source, logical state, and evidence identities;
- refusal of future pin schema versions and unresolved evidence identities.

The fixture OCR implementation is deliberately deterministic and exists only inside the runtime
test module. It proves orchestration and contract composition, not OCR or table quality. The table
stage is the qualified bounded rule-based engine. External electronics semantics remain owned by
Datasheet-cli; Ferrodoc only supplies the generic state/evidence pin that such a result must retain.

Embedded/process response parity remains mandatory for layout, tables, OCRS, optional Tesseract,
and the experimental command adapter. Protocol malformed, partial, oversized, legacy, and scoped
fixtures remain versioned binary oracles. The portable CI slice runs core, IR, protocol, table,
runtime, and CLI tests on Linux, macOS, and Windows. JSON and Markdown goldens contain no host paths,
timestamps, process identifiers, or platform line endings.

The optional Tesseract CLI oracle expects OCR-derived layout: the uppercase first line is a heading
and the following line is a paragraph. Full-page OCR evidence is retained but not simultaneously
selected with its derived layout regions, preventing duplicated body text. Model-backed OCRS
quality, representative external datasheet extraction, corpus quality, and hardware-class resource
measurements remain genuinely environmental evidence; they are not inferred from this fixture.
